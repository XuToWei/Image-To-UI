# Emberfall 示例说明

输入：`../source/design/emberfall-ui-mockup.png` 和 `../source/sprites/`。

仓库仅保留便于阅读和导入的结果：

- `ui_structure.json`：91 个节点、4 组排列、1 个含两条记录的列表。
- `comparison.png` / `reconstruction.png`：原尺寸 1672×941 的对比与重建。
- `state-review.png`：五个导航按钮各自的普通／选中状态。
- `resolution-review.png`：1600×900、1920×1080、1672×1080 的布局预览。

## 状态与适配

底部五个导航按钮都声明 `normal`、`selected`，默认仅天赋按钮选中。
根据中间按钮的放大外观推断同组的选中样式，各按钮保留自己的图标。
放大装饰超出普通布局框约 22–23 像素，这是本例有意保留的视觉重叠。
互斥、点击事件和业务状态由使用方实现。

背景固定为 1672×941 并居中：较小画布裁切背景，较大画布出现留边。
左侧两条任务记录保持紧凑尺寸，无滚动证据；右侧操作组用上／中／下
响应式约束随高度分布。其他 HUD、导航和进入按钮按构图保持尺寸与边缘关系。
伸缩决策取决于整体留白和交互布局，不能仅由是否为列表或滑动区决定。

Unity 导出为标准 UGUI 组件。横排／竖排／网格会生成相应 LayoutGroup，
不添加 LayoutElement。均匀间距在 Unity 导出时折算为参考尺寸下的固定值，
与 Python 在其他尺寸下重新分配间距的预览规则有所不同。

## 已知限制

素材缺少中央角色、头像、准确的背包与天赋徽章、原始字体；使用提供的图标
及 Georgia 作近似。部分面板和底座装饰也与原图不同。状态条素材已烘焙填充，
没有独立填充图层或数值范围，因此未虚构可驱动的进度条。

本例完成过原尺寸结构与视觉审计（零错误、零警告），并检查了八个尺寸／状态
场景。中间网格、裁图、逐场景 trace 和本机工作流记录不随示例提交。
需要重新运行完整工作流时，使用新的 `test/output-local` 目录，遵循 skill。
